重點概念

Key Concepts · 模型選型 → RAG → Prompt 技巧 → 微調 → 評估指標

01

模型選型考量

Model Selection

依任務類型、效能需求（準確度/延遲/可靠度）、限制（運算資源/資料可用性）、合規與成本綜合評估。

模型愈大愈精準但成本愈高
🎛️
02

推論參數

Inference Parameters

調整隨機性/多樣性、輸出長度與終止條件，在創意多樣性與一致連貫性間取得平衡。

Temperature、Top-p、Top-k
📚
03

檢索增強生成

Retrieval Augmented Generation

在推論時檢索外部領域資料作為上下文，讓回應基於最新私有資料，成本遠低於微調。

Bedrock Knowledge Bases
🗄️
04

向量資料庫

Vector Search Databases

OpenSearch Service/Serverless、Aurora PostgreSQL、RDS for PostgreSQL、Neptune ML、MemoryDB、DocumentDB 皆支援向量搜尋。

🤖
05

Bedrock Agents

Bedrock Agents

串接結構化提示、推理步驟與外部資料源，讓 FM 能規劃步驟、呼叫工具以完成多步驟任務。

✍️
06

Prompt 技巧

Prompting Techniques

Zero-shot（無範例）、Few-shot（少量範例）、Chain-of-thought（拆解推理步驟）、Prompt Tuning（調整提示向量）。

🛡️
07

對抗式提示風險

Adversarial Prompting

Exposure 洩密、Prompt Injection 注入惡意指令、Jailbreaking 繞過限制、Hijacking 劫持、Poisoning 資料污染。

🎓
08

預訓練與微調

Pretraining & Fine-tuning

預訓練習得廣泛能力；微調用小量標記資料調整權重，需留意「災難性遺忘」；持續預訓練可疊加新知識。

指令微調 · RLHF
📏
09

生成式 AI 評估指標

Evaluation Metrics

ROUGE 用於摘要、BLEU 用於翻譯、BERTScore 評估語意相似度，皆是初步的自動化評估工具。

✓

隨堂測驗考點

Knowledge Checks
Knowledge Check 1
要為 RAG 選擇支援相似度搜尋與向量儲存的資料庫服務，選哪兩個？
✓

Amazon OpenSearch Service 與 Amazon RDS for PostgreSQL（具 pgvector 擴充）。

Knowledge Check 2
想讓模型學會理解並遵循指示、產出引導式回應，該用什麼技巧？
✓

指令微調（Instruction Tuning），而非單純預訓練或持續預訓練。

⭐

一句話總結

區分「Prompt Engineering → RAG → 微調」三種客製化手段的適用情境與成本，是 Domain 3 的核心判斷題型。
